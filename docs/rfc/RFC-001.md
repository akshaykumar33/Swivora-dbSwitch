# RFC-001: Universal Schema Intermediate Representation (IR) & Capability Detection System

## Proposal Status
- **State**: APPROVED
- **Author**: Chief Software Architect
- **Target Release**: MorphDB v1.0.0

---

## Abstract

This RFC proposes the design of MorphDB's **Universal Schema Intermediate Representation (IR)** and the runtime **Capability Detection Engine**. This architecture enables defining schemas once in TypeScript and safely deploying them across SQL relational databases and NoSQL document stores.

---

## Detailed Specification

### Schema Intermediate Representation Structure

```typescript
export interface ColumnIR {
  readonly name: string;
  readonly type: 'uuid' | 'string' | 'integer' | 'datetime' | 'json' | 'boolean';
  readonly isPrimaryKey: boolean;
  readonly isNullable: boolean;
  readonly isUnique: boolean;
  readonly defaultValue?: unknown;
}

export interface RelationIR {
  readonly name: string;
  readonly type: 'one-to-one' | 'one-to-many' | 'many-to-many';
  readonly targetEntity: string;
  readonly foreignKey: string;
}

export interface SchemaIR<T = unknown> {
  readonly entityName: string;
  readonly columns: ReadonlyMap<string, ColumnIR>;
  readonly relations: ReadonlyMap<string, RelationIR>;
  readonly indexes: ReadonlyArray<IndexIR>;
}
```

## Rationale & Architecture Analysis

### Why?
Provides a declarative single source of truth for both relational DDL generators and document validation schemas.

### Tradeoffs
Polyglot primitive types must abstract away database-specific type extensions (e.g. Postgres `citext` vs Mongo `string`).

### Future Scalability
Supports future schema translation to GraphQL SDL, OpenAPI JSON Schemas, and Protobuf files.
